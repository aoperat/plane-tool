사이드바 — 프로젝트 / 작업 표면 구분 목업

요구사항: 다크 모드에서는 작업이 프로젝트보다 밝게, 라이트 모드에서는 작업이 조금 어둡게(또는 바탕이 어둡고 작업이 떠 보이게) — 프로젝트 층과 할 일 층이 한눈에 구분되도록. 아래 두 방향을 다크/라이트로 비교.

현재 상태 (비교 기준)

프로젝트 헤더와 작업이 같은 패널 표면 위에 있어, hover 전에는 들여쓰기와 글자 크기로만 구분된다.

A안 — 작업 카드 승격 (권장)

사이드바 바탕을 반 단계 가라앉히고 작업을 카드로 띄운다. 다크: 바탕 #131519 위에 작업 #1d2027(+테두리) — 작업이 또렷하게 밝다. 라이트: 회색 바탕 #eef0f3 위에 흰 카드 — 작업 주변이 어두워져 같은 위계가 생긴다. 프로젝트 헤더는 바탕에 남아 자연스럽게 "구역 이름표"로 읽힌다.

B안 — 프로젝트 헤더 침강

작업 영역은 지금 그대로 두고 프로젝트 헤더만 가라앉은 띠로 만든다. 다크: 헤더 띠 #101216 — 상대적으로 작업 영역이 밝아 보인다. 라이트: 헤더 띠 #e9ecf0 — 작업 영역(흰색)과 구분. 변경 범위가 가장 작지만 A안보다 층 대비는 약하다.

구현 메모 — 실제 반영 시 src/shared/app.css에 표면 토큰 2개만 추가하면 된다: --surface-list(사이드바 바탕)와 --surface-task(작업 카드). A안은 .sb-body 배경을 --surface-list로, .task에 배경/테두리를 주고 기존 hover(--panel-2)를 카드 hover 색으로 교체. 진행 중 카드의 border-beam 효과(.task.in-progress::before)는 카드 테두리가 생겨도 그대로 동작한다. B안은 .grp 배경만 바꾸면 끝(단, sticky 헤더라 스크롤 시 띠가 위에 붙는 점은 동일).
