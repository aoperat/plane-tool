# 작업 전광판 캐러셀 설계

## 목적

PC가 유휴 상태가 되었을 때 전체 사이드바를 자동으로 열지 않고, 화면을 가리지 않는
작은 전광판에서 사용자가 지금 봐야 할 작업을 한 건씩 보여준다. 전광판은 읽기와
가벼운 진입만 담당하고, 전체 탐색과 관리는 기존 사이드바가 담당한다.

## 사용자 경험

- 기존 `유휴 시 사이드바 자동 열기` 동작을 `유휴 시 작업 전광판 표시`로 대체한다.
- 전광판은 설정된 모니터의 우측 하단, 작업 표시줄 위에 포커스를 빼앗지 않고 표시된다.
- 한 번에 작업 한 건만 표시하며 프로젝트명, 작업 제목, 마감 또는 우선순위, 현재
  순번을 제공한다.
- 완료·취소 작업을 제외한 현재 사용자 담당 작업 전체를 후보로 삼는다. 로컬 날짜의
  `YYYY-MM-DD` 값으로 비교하며, 아래의 첫 번째로 일치하는 배타적 그룹에 넣는다.
  1. 마감일이 오늘보다 이전인 `지연`
  2. 마감일이 오늘인 `오늘 마감`
  3. 상태 그룹이 `started`인 `진행 중`
  4. 그 밖의 `나머지 작업`
  미래 시작일·미래 마감일·날짜 없는 미완료 작업도 네 번째 그룹에 포함한다. 같은
  그룹에서는 마감일이 빠른 작업을 먼저 두고, 마감일이 같거나 없으면 API에서 받은
  안정적인 순서를 유지한다.
- 7초마다 다음 작업으로 전환한다. 마지막 작업 다음에는 첫 작업으로 돌아간다.
- 전환은 짧은 페이드로 처리하고, 하단의 얇은 진행선으로 다음 전환 시점을 알린다.
- 포인터를 올리거나 클릭 후 키보드 포커스가 들어오면 자동 전환을 멈춘다. 포인터가 벗어나면
  남은 시간이 아니라 새로운 7초 주기로 재개한다.
- 좌우 버튼으로 이전·다음 작업을 탐색할 수 있다. 수동 탐색 후에도 7초 주기를 새로
  시작한다.
- 작업 본문을 클릭하면 기존 작업 편집 창을 연다. 전역 단축키 `F2`를 누르면 전광판을
  먼저 숨긴 뒤 기존 사이드바 토글 동작을 수행한다. 전광판이 키보드 입력을 직접 받을
  필요는 없다. 닫기 버튼은 현재 유휴 세션 동안 전광판을 다시 표시하지 않는다.
- 사용자 입력이 재개되어 유휴 상태가 끝나면 전광판은 자동으로 닫힌다.

## 빈 상태와 실패 처리

- 표시할 미완료 작업이 없으면 `남은 작업이 없습니다`를 한 번 보여주며 캐러셀은
  동작하지 않는다.
- 네트워크 요청이 실패했지만 캐시가 있으면 캐시된 작업을 사용하고 프로젝트명 옆에
  `오프라인 · HH:MM` 배지를 표시한다.
- 네트워크 오류인데 캐시가 없거나 인증·설정·서버 오류가 발생하면
  `작업을 불러오지 못했습니다`와 새로고침 액션을 보여준다. 새로고침은 같은 조회를
  다시 시도하고 성공 시 7초 전환 주기를 새로 시작한다.
- 작업 제목은 한 줄 말줄임 처리하고 전체 제목은 툴팁으로 제공한다.

## 창과 구성 요소

### Tauri 창

`ticker` 라벨의 독립 창을 추가한다. 투명 배경, 장식 없음, 항상 위, 초기 숨김으로
생성한다. 창 크기는 540×64 논리 픽셀을 기본으로 하되 디스플레이 배율을 따른다.

Windows에서는 선택된 모니터의 작업 영역을 `GetMonitorInfoW.rcWork`로 조회하는 Rust
헬퍼/커맨드를 추가한다. 논리 크기를 물리 픽셀로 한 번 변환한 뒤 작업 영역의 오른쪽·
아래쪽에서 각각 16 논리 픽셀에 해당하는 여백을 두고 배치한다. 이 좌표를 사용할 수
없는 플랫폼이나 조회 실패 시에는 기존 모니터의 오른쪽 아래 좌표로 폴백한다.

전광판은 처음 표시할 때만 비활성 창으로 열어 현재 앱의 포커스를 빼앗지 않는다. 표시
후에는 클릭과 Tab 조작을 위해 focusable을 복원하므로 사용자가 클릭하면 활성화될 수
있다. `F2` 전역 단축키는 백엔드에서 전광판 숨김 이벤트를 먼저 보낸 뒤 기존 사이드바
토글 이벤트를 보낸다. 전광판은 일반 blur만으로 숨지 않고, 유휴 종료·닫기·F2에서 숨는다.

### 프런트엔드

`src/ticker/`에 전용 HTML, 스타일, 진입점과 순수 로직을 둔다. 순수 로직은 작업 정렬,
현재 인덱스 보정, 다음/이전 순환을 담당한다. 테마 토큰과 공용 타입·IPC는
`src/shared/`에서 재사용한다.

`vite.config.ts`의 다중 페이지 입력과 `src-tauri/tauri.conf.json`의 창 목록에 ticker를
등록하고, Tauri capability가 창 라벨을 제한한다면 ticker 라벨도 추가한다.

### 백엔드 이벤트

기존 유휴 감지기의 세션당 1회 게이트는 유지하되 `open-sidebar` 대신 `open-ticker`
이벤트를 전광판에 보낸다. 유휴 종료 시에는 전광판에 닫기 이벤트를 보내고, 기존
사이드바의 자동 열림 보호 상태는 제거한다. 닫은 뒤 같은 유휴 세션에 다시 열리지 않는
동작은 기존 게이트의 `fired` 상태가 보장한다.

현재 `refresh-sidebar`, `item-updated`, `item-deleted`를 sidebar 라벨에만 보내는 모든
발행 지점은 ticker에도 같은 payload를 보낸다. 전광판은 필드 패치 후 목록을 재정렬하고
현재 작업 ID를 유지한다. 삭제·완료·취소로 현재 작업이 후보에서 사라지면 보정된 같은
인덱스의 다음 작업을 표시한다. 전체 새로고침 이벤트는 다시 조회한다.

## 데이터 흐름

1. 유휴 감지기가 설정된 임계시간을 넘긴다.
2. 백엔드가 `ticker` 창에 `open-ticker`를 전송한다.
3. 전광판은 기존 사이드바 조회 명령을 사용해 오늘 전후 범위의 데이터를 한 번 가져온다.
4. 현재 사용자에게 할당된 작업에서 완료·취소를 제외하고 배타적 그룹 규칙으로 정렬한다.
5. 첫 작업을 즉시 렌더링하고 7초 타이머를 시작한다.
6. 데이터 갱신이나 작업 편집 이벤트를 받으면 목록을 다시 계산하고, 가능하면 현재 작업
   ID를 유지한다. 현재 작업이 사라졌다면 보정된 같은 인덱스의 다음 작업을 표시한다.
7. 유휴 종료 또는 닫기 입력을 받으면 타이머를 정리하고 창을 숨긴다.

초기 구현에서는 별도 캐시나 동기화 계층을 만들지 않는다. 전광판 표시 시 유휴 세션당
한 번만 전체 조회하고 폴링하지 않는다. 따라서 전광판과 사이드바가 연이어 열리면 각각
한 번씩 N+1 조회가 발생할 수 있으며, 네트워크 실패 시에만 기존 백엔드 오프라인 캐시로
폴백한다. 공유 TTL/요청 병합은 데이터 기반 다지기 로드맵에서 별도로 다룬다.

## 설정

- 기존 `idle_open_enabled`와 `idle_open_minutes` 저장 필드는 호환성을 위해 유지한다.
- 설정 문구만 `유휴 시 작업 전광판 표시`, `전광판 표시까지의 유휴 시간(분)`으로 바꾼다.
- 첫 버전의 전환 시간은 7초 고정이다. 별도 설정은 실제 사용 후 필요성이 확인되면 추가한다.
- 이전 설정에서 자동 열기가 켜져 있던 사용자는 업데이트 후 전광판 자동 표시가 켜진
  상태로 자연스럽게 이전된다.

## 접근성과 키보드

- 프로젝트와 메타데이터는 색상뿐 아니라 텍스트로 구분한다.
- 텍스트와 배경은 WCAG AA 수준의 대비를 목표로 한다.
- 좌우 버튼, 작업 본문, 닫기 버튼에는 접근 가능한 이름과 명확한 포커스 표시를 둔다.
- 애니메이션 감소 설정이 켜져 있으면 페이드 없이 즉시 교체한다.

## 테스트

- 순수 로직 단위 테스트: 우선순위 정렬, 동률 안정성, 빈 목록, 인덱스 순환, 목록 변경 시
  현재 작업 유지와 인덱스 보정.
- Rust 단위 테스트: 기존 `IdleOpenGate`를 이용한 유휴 세션당 한 번 표시, 비활성 설정,
  유휴 종료 후 다음 세션 재무장.
- 순수 캐러셀 컨트롤러 테스트(Vitest fake timer): 7초 전환, 일시정지와 새 주기 재개,
  좌우 탐색. DOM 환경 의존성이 없는 현재 테스트 구성에서는 hover, 긴 제목 말줄임,
  모션 감소 스타일은 수동 확인한다.
- 수동 확인: Windows 배율 100%/125%/150%, 다중 모니터, 작업 표시줄 위치, 전광판이
  포커스를 빼앗지 않는지, 클릭과 F2 전환이 정상인지 확인한다.

## 범위 밖

- 관리자용 팀 리스크 캐러셀
- 전환 시간과 위치의 사용자 지정
- 드래그로 전광판 위치 변경
- 전광판에서 상태·담당자·마감일을 직접 편집
- OS 알림 센터 연동

이 항목들은 작업자용 전광판의 실제 사용성이 검증된 뒤 별도 기능으로 다룬다.
