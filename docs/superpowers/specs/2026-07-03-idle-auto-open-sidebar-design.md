# PC 유휴 시 사이드바 자동 열기 — 설계 스펙

- 날짜: 2026-07-03
- 상태: 사용자 승인 대기

## 목적

사용자가 PC에 일정 시간 입력(키보드/마우스)을 하지 않으면 사이드바를 자동으로
열어, 자리로 돌아왔을 때(또는 잠시 쉬는 동안) 진행 중인 작업 목록이 바로 보이게
한다.

## 유휴 감지 방식

- Rust 백엔드에서 Windows `GetLastInputInfo` API로 마지막 입력 이후 경과
  시간(밀리초)을 조회한다. 전역 입력 후킹이 아니라 OS가 이미 기록해 둔
  타임스탬프를 읽는 방식이라 가볍고 권한 문제가 없다.
- `windows` crate 의존성을 추가한다 (`Win32_UI_Input_KeyboardAndMouse`,
  `Win32_System_SystemInformation` feature).
- 백그라운드 tokio 태스크가 **5초 간격**으로 폴링한다.

## 동작 규칙

1. 유휴 시간이 기준(설정값, 기본 3분)을 넘으면 `sidebar` 창에 **열기 전용**
   이벤트 `open-sidebar`를 emit한다. 기존 `toggle-sidebar`를 재사용하지 않는
   이유: 이미 열려 있을 때 오히려 닫아 버리는 사고를 막기 위해.
2. 사이드바(`src/sidebar/main.ts`)는 `open-sidebar` 수신 시 닫혀 있으면 연다.
   이미 열려 있으면 아무것도 하지 않는다. 단, **포커스는 가져가지 않는다**
   (`setFocusable(false) → show → setFocusable(true)`): 포커스를 가지면
   사용자가 자리에 없는 동안 어떤 포커스 변화(화면 잠금, 알림, 다른 앱
   활성화)든 blur 자동 숨김을 발동시켜 사이드바가 저절로 닫히고, 복귀한
   사용자의 입력을 가로채는 문제도 있다. 포커스가 없으면 focus 이벤트 기반
   데이터 갱신이 안 돌므로 리스너에서 직접 갱신을 호출한다.
3. **유휴 세션당 1회만** 자동 열림: 한 번 열고 나면(사용자가 닫았든 그대로
   두었든) 입력이 재개되어 유휴 상태가 풀릴 때까지 다시 emit하지 않는다.
   백엔드에서 "유휴 시간이 기준 아래로 내려감 → 플래그 리셋"으로 구현한다.
4. **자동으로 열린 사이드바는 키보드/마우스 입력이 재개되기 전까지는 닫히지
   않는다.** 무인 상태에서는 화면 잠금·알림·다른 앱 활성화 등이 얼마든지
   blur를 일으킬 수 있으므로, 자동 열림 상태(`autoOpened`) 동안은 blur 자동
   숨김을 무시한다. 해제 경로는 두 가지: (a) 백엔드 워처가 유휴 세션 종료
   전환에서 `idle-ended` 이벤트를 emit(폴링 5초 이내), (b) 사용자가 사이드바를
   직접 조작(pointerdown). 해제 후에는 평소 규칙(blur 숨김, 핀 고정 시 유지)으로
   복귀하며, 입력 재개 시 강제로 닫지는 않는다.

## 설정

`Settings`(`src-tauri/src/config.rs`)에 두 필드 추가, 설정 화면
(`src/settings/`)에 UI 추가:

| 필드 | 타입 | 기본값 | UI |
|---|---|---|---|
| `idle_open_enabled` | bool | `true` (켬) | 체크박스 "유휴 시 사이드바 자동 열기" |
| `idle_open_minutes` | u32 | `3` | 숫자 입력(분), 최소 1 |

- 둘 다 `#[serde(default = ...)]`로 기존 저장 파일과 호환.
- 폴링 태스크는 매 tick마다 설정을 다시 읽어(`config::load_settings`) 설정
  변경이 앱 재시작 없이 반영되게 한다. 5초 간격 파일 읽기는 부담이 없다.

## 엣지 케이스

- **전체화면 앱(동영상 시청 등)**: 입력이 없어도 사용자가 화면을 보고 있을 수
  있으나 1차 버전에서는 감지하지 않는다 (YAGNI — 불편하면 추후 추가).
- **잠금 화면/모니터 꺼짐**: 열려도 보이지 않을 뿐 해가 없음. 대응 안 함.
- **비 Windows 빌드**: 유휴 조회 함수는 `#[cfg(windows)]`로 감싸고, 그 외
  플랫폼에서는 기능이 비활성화된 것처럼 동작한다 (현재 배포 대상은 Windows뿐).

## 테스트

- 유휴 판정 상태 머신(경과 시간 + 기준 + 1회성 플래그 → "이번 tick에 열어야
  하는가")을 OS 호출과 분리된 순수 함수/구조체로 만들어 Rust 단위 테스트 작성:
  - 기준 미달 → 열지 않음
  - 기준 초과 첫 tick → 열음
  - 기준 초과 지속 → 다시 열지 않음
  - 유휴 해제 후 재초과 → 다시 열음
  - `idle_open_enabled=false` → 절대 열지 않음
- 설정 직렬화 round-trip 및 기존 설정 파일(새 필드 없음) 역직렬화 기본값 테스트.
