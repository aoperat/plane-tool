# 빠른 추가 v2(한눈에 보기) + 프로젝트 검색 — 설계 스펙

- 날짜: 2026-08-10
- 상태: 사용자 승인 대기
- 목업: `docs/mockups/quickadd-v2-mockup.html` (클릭 동작하는 인터랙티브 목업)

## 목적

지금의 빠른 추가는 담당자·시작일·마감일·상태·우선순위가 **전부 칩 하나로 접혀** 있다.
값을 확인하려면 눌러야 하고, 바꾸려면 드롭다운을 열었다 닫아야 한다. 게다가 팝오버
엘리먼트가 하나뿐이라(`fieldPopover`) **한 번에 한 항목만** 펼칠 수 있다 — 상태를 고르는
동안 담당자와 날짜는 가려진다.

**v2**는 이 다섯 항목을 라벨 붙은 다섯 줄로 펼쳐, 확인도 변경도 제자리 클릭 한 번에
끝내는 레이아웃이다. 창은 660px로 넓어진다. 좁은 화면이나 "제목만 던져 넣는" 사용
패턴에는 지금 레이아웃이 여전히 낫기 때문에 **한쪽으로 갈아엎지 않고 설정에서 고르게**
한다.

곁들여, 하단 **프로젝트 선택을 검색되는 드롭다운**으로 바꾼다. 이 자리는 두 레이아웃이
공유하므로 v1 사용자도 같이 혜택을 본다.

## 범위 밖

- **사이클 선택** — 별도 스펙(`2026-07-23-quickadd-cycle-selection-design.md`)이 있고 아직
  미구현이다. v2가 먼저 들어가면 사이클 줄은 여섯 번째 행으로 자연스럽게 붙는다.
- **편집 모달(`src/editmodal/`)** — 지금의 칩 행 문법을 유지한다. 이미 있는 작업을 고치는
  화면이라 "한눈에 훑고 만든다"는 v2의 동기가 약하다.
- **새 필드 추가**(모듈·레이블·예상 시간 등) — v2는 있는 항목을 펼치기만 한다.
- **영타 오타 보정 검색**(`ejwkdls` → 디자인) — 아래 "프로젝트 검색" 참고.

## 핵심 설계 결정

1. **두 레이아웃은 상태와 제출 경로를 공유한다.** 다른 것은 그 상태를 그리는 방식뿐이다.
   따라서 `main.ts`를 *상태*와 *렌더러*로 가르고, 렌더러만 둘 둔다. 제출·창 크기·전역
   키보드 계약은 한 곳에 남는다.
2. **형태로 선택 방식을 구분한다.** 오목한 트랙 안의 세그먼트 = **하나만 고름**(상태·
   우선순위·날짜 프리셋), 트랙 없는 낱개 칩 = **여러 개 가능**(담당자). 같은 모양에 다른
   규칙을 태우지 않는다.
3. **창 폭은 레이아웃이 정한다** — v1 540px, v2 660px. `resizeToFit`이 높이만 계산하던
   것을 폭도 함께 넘기도록 바꾼다.
4. **프로젝트 검색은 v2와 독립적으로 먼저 낼 수 있다.** 구현 순서 1단계로 둔다.
5. **설정을 바꾸면 이벤트로 즉시 반영한다.** 빠른 추가 창은 부팅 때 만들어져 숨었다
   보였다 할 뿐 재로드되지 않으므로, `save_settings`가 `quickadd` 창에 이벤트를 쏘고
   창은 렌더러를 갈아끼운다. `select-project` 이벤트와 같은 관례다.
6. **기본값은 기존 레이아웃(v1)이다.** 자동 업데이트로 창 모양이 말없이 바뀌면 안 된다.
   CHANGELOG 줄이 설정 위치를 알린다. (한 줄만 고치면 뒤집을 수 있다 — 아래 "설정" 참고.)

## 파일 구조 (`src/quickadd/`)

`main.ts`는 지금 723줄에 상태·DOM·창 크기·키보드가 뒤섞여 있다. 여기에 두 번째 레이아웃을
얹으면 1,000줄을 넘고 "어느 레이아웃 코드인지"가 섞인다. 레이아웃을 더하기 **전에**
가른다(동작 변화 없는 리팩터, 구현 순서 2단계).

```
src/quickadd/
  main.ts            부팅, 레이아웃 선택, 창 크기, 제출, 전역 키보드 계약
  state.ts           폼 상태와 변경 함수. DOM을 모른다 — 순수, 테스트 대상.
  layoutCompact.ts   v1 칩 행 렌더러 (지금 코드를 옮긴 것)
  layoutExpanded.ts  v2 필드 격자 렌더러 (새로 씀)
  projectPicker.ts   검색되는 프로젝트 드롭다운 (두 레이아웃 공용)
```

**렌더러 계약** — `main.ts`가 두 레이아웃을 같은 방식으로 다루기 위한 최소 인터페이스다.

```ts
export interface LayoutHandle {
  /** 상태가 바뀌었으니 다시 그린다. */
  render(): void;
  /** 열려 있는 팝오버·드롭다운을 모두 닫는다(제출·창 닫기 직전에 부른다). */
  closeOverlays(): void;
  /** 이 레이아웃이 요구하는 창 폭(px). */
  readonly width: number;
  /** 창 높이 계산에 포함해야 할, 카드 밖으로 떠 있는 요소의 아래 끝(px).
   *  떠 있는 게 없으면 0. `resizeToFit`이 카드 높이와 이것 중 큰 쪽을 쓴다. */
  overlayBottom(): number;
  /** 이벤트를 떼고 DOM을 비운다(레이아웃 전환 시). */
  destroy(): void;
}

export function mountCompact(root: HTMLElement, state: FormState): LayoutHandle;
export function mountExpanded(root: HTMLElement, state: FormState): LayoutHandle;
```

`state.ts`가 갖는 것: 제목·설명·`assigneeIds`·`startChoice`/`startCustomDate`·`dueChoice`/
`dueCustomDate`·`priority`·`stateGroup`·`selectedId`·`members`. 그리고 지금 `main.ts`에
있는 `shiftDateField`(시작일과 마감일이 교차하지 않게 서로를 끌고 가는 로직),
`resolveDateChoice`, `dateChoiceLabel`, `toggleAssignee`, `resetFields`를 여기로 옮긴다.
이들은 DOM을 만지지 않으므로 그대로 테스트할 수 있다.

## v2 레이아웃 (`layoutExpanded.ts`)

카드 폭 660px. 제목 줄 아래에 라벨 붙은 다섯 줄이 온다.

| 행 | 컨트롤 | 상호작용 |
|---|---|---|
| 담당자 | 낱개 아바타 칩(나 포함 4칸) + `+N` | 클릭=단독 지정, Ctrl+클릭=토글 |
| 상태 | 세그먼트 트랙 5개 (`STATE_ORDER`) | 클릭 |
| 우선순위 | 세그먼트 트랙 5개 (`PRIORITY_ORDER`) | 클릭 |
| 시작일 | 프리셋 트랙 3개 + `‹ 2026-08-10(월) ›` | 프리셋 클릭 / ±1일 / 날짜 클릭 |
| 마감일 | 위와 동일 | 위와 동일 |

아이콘과 라벨은 `shared/planeIcons.ts`, 프리셋은 `shared/datePresets.ts`를 그대로 쓴다 —
v2를 위한 새 상수는 만들지 않는다.

**행 분리** — 행 사이에는 `--border`를 45% 투명하게 깐 실선 하나만 둔다. 다섯 줄 위에
진한 선 네 개를 그으면 팝업 하나가 표처럼 무거워진다.

**담당자 행**

- 인라인에 보이는 사람: **"나"를 항상 맨 앞**에 두고, 그 뒤로 프로젝트 멤버 목록 순서대로
  채워 **4칸**("나" 포함). 나머지는 `+N`. 4는 660px 폭에 이름 칩 넷과 `+N`이 넉넉히 들어가는
  수를 잡은 것이므로, 실제로 붙여 보고 좁으면 줄인다.
- **이미 지정된 담당자는 무조건 인라인에 보인다.** 팝오버에서 고른 사람이 `+N` 뒤로
  숨으면 "몇 명 붙었는지" 세러 다시 열어야 하므로 v2의 목적이 무너진다. 지정된 사람이
  4명을 넘으면 인라인 칸이 그만큼 늘고 `+N`이 줄어든다.
- `assigneeIds`가 비면 "나"가 선택 표시된다(서버가 호출자에게 할당) — v1과 같은 규칙.
- `+N` 팝오버는 담당자 칩 바로 아래에 뜨는 기존 `.dd-item` 목록이다.

**날짜 행**

- 프리셋 클릭 → `startChoice`/`dueChoice`를 그 프리셋으로.
- 스테퍼 `‹` `›` → 기존 `shiftDateField(kind, ±1)`. 시작일을 마감일 뒤로 밀면 마감일이
  따라가고, 마감일을 시작일 앞으로 당기면 시작일이 따라오는 기존 보호 로직을 그대로 쓴다.
- 날짜 텍스트 클릭 → 네이티브 날짜 선택기(`input[type=date]`의 `showPicker()`).
- **프리셋 밖 날짜면 프리셋 세 개가 모두 꺼진다**(`choice === "custom"`). 지금 무엇이
  들어갈지는 스테퍼의 실제 값 하나만 말한다.

**설명** — v1처럼 토글로 남기고, 제목 줄 오른쪽 끝에 둔다. 늘 펼쳐두면 팝업이 항상
높아지는데 실제로 설명을 쓰는 비율은 낮다. 토글을 꺼도 입력한 텍스트는 남고 제출된다
(지금 동작 유지).

## 키보드

**그대로 유지** — `Ctrl+Enter` 제출(포커스 위치·팝오버 상태와 무관), `Esc` 닫기,
`PgUp/Dn` 시작일 ±1일, `Ctrl+PgUp/Dn` 마감일 ±1일.

**v2에서 바뀌는 것**

| 키 | v1 | v2 |
|---|---|---|
| `Tab` | 칩 사이 이동(브라우저 기본) | **행 사이** 이동 |
| `←` `→` | 칩 사이 이동 | **행 안** 세그먼트 이동 |
| `Enter` | 팝오버 항목 선택 | 포커스한 세그먼트 선택 |
| `Space` | 담당자 팝오버에서 토글 | 담당자 칩 토글(같은 뜻) |

담당자 행은 v1 팝오버의 다중 선택 계약을 인라인으로 옮긴 것이다 — `Enter`는 단독 지정,
`Space`는 토글.

휠 스크롤(`shared/wheelCycle.ts`)은 세그먼트 하나가 아니라 **트랙 전체**에 건다. 트랙 위에서
휠을 굴리면 값이 앞뒤로 움직인다. 상태·우선순위는 순서 있는 척도이므로 v1처럼 양 끝에서
멈추고(순환하지 않고), 날짜는 ±1일이다.

## 프로젝트 검색 드롭다운 (`projectPicker.ts`)

지금은 프로젝트가 그냥 나열된다. 목록 맨 위에 검색창을 붙이고 **열자마자 커서를 거기**
둔다. 그냥 눌러 고르는 흐름은 그대로고, 검색은 원할 때만 쓰는 추가 경로다.

- 열리는 방향은 지금과 같이 **아래쪽**이다(위로 열면 프로젝트가 많을 때 창 위 모서리를
  넘어가 클릭할 수 없는 부분이 생긴다 — `app.css`에 이미 적힌 이유). 폭은 230 → **272px**.
- 구성: `검색창(돋보기 + input + 개수)` / `목록` / `하단 키보드 힌트`.
- 개수는 검색 전 `10개`, 검색 중 `2/10`.
- 목록은 `max-height: 208px`(약 7줄) + 스크롤. 프로젝트가 많아도 창이 계속 자라지 않는다.
- 결과가 없으면 `일치하는 프로젝트가 없습니다`.
- 키보드: `↑` `↓` 이동, `↵` 선택, `Esc` 닫기. **커서는 검색창에 머무른다** — 좁히다가
  바로 Enter로 고를 수 있다. 이 세 줄을 드롭다운 하단에 상시 표기한다.
- 키보드 커서의 초기 위치는 현재 선택된 프로젝트. 필터에 걸러져 사라지면 첫 줄로 내려간다.
- 열 때마다 검색어는 비운다.

**매칭 규칙** (`src/shared/projectSearch.ts` — 순수, 테스트 대상)

```ts
export interface ProjectMatch {
  project: Project;
  /** 이름에서 맞은 구간 [시작, 끝). 강조에 쓴다. */
  range: [number, number];
}

/** 이름 부분 일치(대소문자 무시) 또는 초성 일치. 입력 순서를 유지한다. */
export function filterProjects(projects: Project[], query: string): ProjectMatch[];
```

- **부분 일치** — 앞글자가 아니라 이름 어디에 걸려도 남는다(`디자인 시스템`을 `자`로,
  `QA 자동화`를 `자`로). 영문은 대소문자를 가리지 않는다.
- **초성 일치** — `ㄷㅈㅇ` → `디자인 시스템`. 한글 음절(U+AC00–U+D7A3)에서
  `(code - 0xAC00) / 588`로 초성 인덱스를 뽑아 비교한다. **검색어가 전부 초성 자모일
  때만** 초성 모드로 본다 — 그러지 않으면 `자` 한 글자가 초성 검색과 섞여 엉뚱한 항목이
  걸린다.
- 맞은 구간은 `<mark>`로 감싼다(사이드바 검색이 이미 쓰는 스타일 재사용). 초성 일치도
  연속된 음절 구간이므로 같은 방식으로 강조된다.
- **영타 오타 보정은 넣지 않는다.** QWERTY↔두벌식 매핑 표와 자모 재조합이 필요한데,
  얻는 것에 비해 오탐이 늘고 코드가 는다. 나중에 필요하면 `filterProjects` 안에서
  세 번째 매칭 규칙으로 더할 수 있다.

**테스트**(`projectSearch.test.ts`): 부분 일치, 대소문자 무시, 초성 일치, 초성+일반 혼합
검색어(초성 모드로 안 빠지는지), 빈 검색어(전체), 무매칭, 반환되는 `range`가 실제 맞은
구간인지.

## 창 크기

`resizeToFit`은 지금 높이만 재고 폭은 540으로 고정돼 있다. 레이아웃이 정한 폭을 쓰도록
바꾼다.

```ts
win.setSize(new LogicalSize(layout.width, height));
```

높이 계산은 지금 방식을 그대로 둔다 — 카드의 실제 렌더 높이와, 떠 있는 요소의 아래 끝
(`layout.overlayBottom()`) 중 큰 쪽. `openPopover`/`dropdown`을 직접 들여다보던 부분이
렌더러 안으로 들어가는 것뿐이다.

**중앙 정렬** — `show_centered`는 `outer_size()`를 읽어 위치를 잡은 뒤 창을 보여준다.
레이아웃 전환은 창이 숨어 있는 동안 일어나고 폭 변경도 그때 끝나므로, 다음 열기는
정상적으로 가운데 온다. 설정을 저장한 **바로 그 순간** F1을 누르면 `setSize`가 아직
안 끝나 한 번은 60px 정도 어긋날 수 있다 — 그 다음 열기부터는 맞는다. 이 경계를 위해
따로 동기화하지 않는다.

## 설정

**Rust** (`src-tauri/src/config.rs`)

```rust
/// "compact"(기존 칩 행) | "expanded"(한눈에 보기)
#[serde(default = "default_quickadd_layout")]
pub quickadd_layout: String,

fn default_quickadd_layout() -> String { "compact".into() }
```

기본값이 `"compact"`인 이유는 위 "핵심 설계 결정" 6번이다. `"expanded"`로 뒤집고 싶으면
이 함수 한 줄만 고치면 된다.

**명령** (`src-tauri/src/commands.rs`) — `save_settings`에 인자를 하나 더한다(지금도 19개짜리
위치 인자 목록이다 — 같은 관례를 따른다). 저장 직후 빠른 추가 창에 알린다.

```rust
let _ = app.emit_to("quickadd", "settings-changed", ());
```

**프론트** — `SettingsDto`(`src/shared/types.ts`)와 `saveSettings`(`src/shared/ipc.ts`)에
`quickadd_layout`을 더한다.

**설정 화면**(`src/settings/index.html`, `main.ts`) — `화면` 섹션의 테마 아래에 select를
하나 더 둔다. 테마와 같은 형태다.

```html
<label>빠른 추가 화면
  <select id="quickaddLayout">
    <option value="compact">컴팩트 — 칩을 눌러 값 바꾸기</option>
    <option value="expanded">한눈에 보기 — 모든 항목 펼쳐 보기</option>
  </select>
</label>
```

**빠른 추가 쪽** — `settings-changed`를 듣고 설정을 다시 읽어, 레이아웃이 바뀌었으면
현재 렌더러를 `destroy()`하고 다른 쪽을 `mount()`한 뒤 `resizeToFit()`. 폼 상태는
`state.ts`에 있으므로 **작성 중이던 초안은 그대로 살아남는다.**

## 구현 순서

각 단계는 그 자체로 동작하는 상태에서 끝난다.

1. **프로젝트 검색** — `shared/projectSearch.ts` + 테스트 → `quickadd/projectPicker.ts` →
   지금 레이아웃에 배선. 여기까지만으로 출하할 수 있다.
2. **상태/렌더러 분리** — `state.ts`, `layoutCompact.ts`로 가르는 리팩터. 동작 변화 없음.
   상태 함수 테스트를 이 단계에서 붙인다.
3. **설정 배선** — Rust 필드 + DTO + 설정 화면 + `settings-changed` 이벤트. 아직 고를 값이
   하나뿐이므로 화면상 변화는 없다.
4. **v2 렌더러** — `layoutExpanded.ts`, 창 폭 전환, 레이아웃 갈아끼우기.
5. **키보드 계약** — v2의 Tab/화살표/Space/Enter와 휠 트랙 배선.

## 아직 안 정한 것

구현에 들어가기 전에 정하면 좋지만, 정하지 않아도 1~4단계는 막히지 않는다.

- **담당자 인라인 정렬 순서** — 지금 안은 "나 먼저, 그 뒤 멤버 목록 순서"다. 대안은
  "최근에 지정한 순서"(localStorage에 프로젝트별로 기록). 실제로 자주 쓰는 사람이 앞에
  오지만, 목록이 열 때마다 달라져 근육 기억이 안 붙는다.
- **상태·우선순위 숫자 단축키** — `Alt+1..5`로 세그먼트를 직접 찍는 안. 넣으면 빠르지만
  외울 것이 늘고, 이미 화살표로 닿는다.
