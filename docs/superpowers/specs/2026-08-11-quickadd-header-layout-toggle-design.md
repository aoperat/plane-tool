# 빠른 추가 헤더 레이아웃 토글 + 신규 안내 — 설계 스펙

- 날짜: 2026-08-11
- 상태: 구현 완료
- 목업: `docs/mockups/quickadd-header-toggle-mockup.html`
- 선행: `2026-08-10-quickadd-v2-design.md` (두 레이아웃과 `quickadd_layout` 설정을 만든 작업)

## 목적

레이아웃을 바꾸려면 설정 창을 열어야 한다. 자주 오갈 만한 선택인데 경로가 멀다.
**헤더에 토글**을 두어 그 자리에서 바꾸게 한다.

그리고 이건 방금 생긴 기능이라 아무도 모른다. **업데이트 후 처음 열 때 한 번**
토글을 가리켜 알린다.

## 핵심 설계 결정

1. **진실은 하나다.** 헤더 토글과 설정 화면은 같은 `quickadd_layout` 값을 쓴다.
   어느 쪽에서 바꾸든 다른 쪽이 따라온다.
2. **토글은 아이콘 2단 세그먼트다.** 현재 상태가 항상 보여야 해서 단일 버튼(누르면
   전환)은 쓰지 않는다 — 아이콘 하나가 "지금 상태"인지 "누르면 될 상태"인지 모호하고,
   닫기 버튼과 크기·테두리가 같아 한 벌로 보인다. 텍스트 2단은 헤더 폭을 두 배 먹고
   제목과 시각적으로 경쟁한다.
3. **안내는 코치마크다.** 토글을 화살표로 직접 가리키고 대상에 링을 둘러 둘을 눈으로
   잇는다. 배지는 무시하고 지나가기 쉽고, 배너는 토글을 가리키지 못한다.
4. **안내가 입력을 막지 않는다.** 포커스는 제목 칸에 그대로 있어, 안내를 무시하고 바로
   타이핑해도 흐름이 끊기지 않는다.
5. **단축키는 두지 않는다.** 자주 오가는 조작이 아니고 외울 것만 는다.

## 토글 (`src/quickadd/index.html`, `main.ts`, `shared/app.css`)

제목과 닫기 버튼 사이에 들어간다. `.seg-track`(필드 격자의 단일 선택 트랙)을 헤더
크기로 줄인 것이라 앱 안에서 새 문법이 아니다 — 켜진 쪽이 accent로 찬다.

**드래그 영역** — 헤더 전체가 `data-tauri-drag-region`이지만 따로 처리할 게 없다.
이 앱은 드래그에서 빠져야 할 요소에 `pointer-events: none`을 주는 방식이라
(`.qa-grip`, `.qa-header-title`), 닫기 버튼처럼 그것만 안 주면 클릭된다. Tauri는
이벤트 대상이 그 속성을 달고 있을 때만 드래그를 시작한다.

**아이콘** — "한 줄이냐 여러 줄이냐" 하나로만 갈린다. 컴팩트는 칩이 한 줄로 늘어선
모양, 한눈에 보기는 라벨+값이 세 줄로 쌓인 모양. **칩은 가로로 길어야 한다** —
폭과 높이가 같으면 14px에서 점 세 개로 뭉개져 사이드바의 "더보기" 버튼과 뜻이 겹친다.

버튼마다 이름을 툴팁으로 붙인다(`bindTip`) — 아이콘만으로는 무엇인지 모른다.

## 저장 (`src-tauri/src/{config,commands,lib}.rs`, `src/shared/ipc.ts`)

`save_settings`는 인자가 20개라 토글 하나 때문에 부르기엔 무겁다. `set_last_project`
선례를 따라 전용 명령을 둔다.

```rust
#[tauri::command]
pub fn set_quickadd_layout(app: tauri::AppHandle, layout: String) -> Result<(), String>
```

`"compact"`/`"expanded"`만 받고 나머지는 거절한다.

**설정 창에 알리는 이유** — 설정 창이 열려 있는 동안 헤더에서 토글하면 그쪽
`<select>`가 낡은 값을 들고 있게 되고, 그 상태로 "저장"을 누르면 방금 바꾼 값을
되돌려 버린다. 그래서 저장 뒤 `settings` 창에 `quickadd-layout-changed`를 쏘고
설정 화면이 그걸 듣고 select를 갱신한다. 반대 방향(설정 → 빠른 추가)은 기존
`settings-changed`가 이미 처리한다. **빠른 추가 창에는 알리지 않는다** — 변경을
시작한 쪽이라 이미 안다.

## 코치마크 (`main.ts`)

- **언제** — 창이 실제로 보일 때(`tauri://focus`)만 띄운다. 부팅 때 도는 `load()`는
  창이 아직 숨어 있어서, 거기서 띄우면 사용자가 못 본 채 남은 횟수만 깎인다.
- **몇 번** — 통틀어 **2회**, 앱 실행당 최대 한 번. 창은 트레이에 살아 있어 포커스가
  여러 번 오가므로 실행당 빗장(`coachShownThisRun`)을 둔다.
- **사라짐** — `알겠어요` 또는 **토글을 직접 조작**하면 완료로 잠근다. 창을 닫거나
  등록해서 치우는 경우는 잠그지 않는다(남은 횟수를 까먹지 않는다).
- **저장 위치** — 화면 취향이라 백엔드 설정이 아니라 이 창의 `localStorage`
  (`qa-layout-coach-shown`). 사이드바가 접힘 상태·탭 선택을 두는 방식과 같다.
- **위치** — 화살표가 토글 한가운데를 가리키게 매번 다시 잰다. 팝업 폭이 레이아웃에
  따라 540↔660으로 달라지고, 레이아웃이 바뀌면 토글도 옮겨가므로 `applyLayout`에서
  안내가 떠 있으면 다시 맞춘다. 좌우로는 팝업 안에 머물게 물린다.
- **창 크기** — `resizeToFit`이 팝오버·드롭다운 아래 끝을 재듯 코치마크도 같이 잰다.

## 범위 밖

단축키, 3회 이상 노출, 사이드바 등 다른 창의 유사 안내, 안내 문구의 버전별 분기.

## 검증

- `cargo check` / `pnpm exec tsc --noEmit` / `pnpm build` / `pnpm test` 전부 통과.
- 실제 `index.html` 마크업과 실제 `app.css`를 헤드리스 브라우저로 렌더해 토글 위치,
  accent 표시, 스포트라이트 링, 말풍선 화살표 정렬을 눈으로 확인했다.
- **Tauri 창으로는 확인하지 못했다** — 드래그 영역과 토글 클릭이 서로 방해하지 않는지,
  안내가 실제로 두 번만 뜨는지는 사람이 눌러봐야 한다
  (`2026-08-10-quickadd-v2-manual-qa.md`와 같은 이유).
