# QuickAdd 트레이 필드 확장 설계

## 배경

F1 QuickAdd 트레이는 현재 제목(title)만 입력받아 작업을 생성한다. 담당자/시작일/마감일/우선순위/진행상태를 지정할 방법이 없어, 생성 후 매번 Plane 웹에서 따로 채워야 했다. 이번 작업은 QuickAdd에서 이 5개 필드를 함께 입력할 수 있도록 확장한다.

## 레이아웃

기존 팝업(제목 입력 → 프로젝트 선택 바) 사이에, 제목 입력 바로 아래 **한 줄 칩(chip) 툴바**를 추가한다. 필드가 많아 한 줄에 안 들어가면 자동 줄바꿈(flex-wrap)된다.

```
┌─────────────────────────────────────────────┐
│ ┃ 작업 제목 입력...                            │  ← 기존 title-input
│  [나 나] [📅 오늘] [🚩 오늘] [▬ 우선순위 없음] [○ Backlog]  │  ← 신규 칩 툴바
├─────────────────────────────────────────────┤
│ [● 프로젝트 선택 ▾]              Enter 추가 · Esc 닫기│  ← 기존 하단 바
└─────────────────────────────────────────────┘
```

각 칩을 클릭하면 프로젝트 선택 드롭다운과 같은 패턴의 작은 팝오버가 열려 값을 고른다.

## 필드 정의

| 필드 | 기본값 | 선택 방식 | 다중 선택 |
|---|---|---|---|
| 담당자 | 나(현재 로그인 사용자) | 워크스페이스 멤버 목록 드롭다운 | 가능 (Plane 실제 동작과 동일) |
| 시작일 | 오늘 | 프리셋(오늘/내일/다음 주=+7일) + `<input type="date">` 직접 선택 | 단일 |
| 마감일 | 오늘 | 프리셋(오늘/내일/다음 주=+7일) + `<input type="date">` 직접 선택 | 단일 |
| 우선순위 | None | 고정 5개 값 드롭다운: none/low/medium/high/urgent | 단일 |
| 진행상태 | Backlog | 고정 5개 표준 그룹 드롭다운: backlog/unstarted/started/completed/cancelled | 단일 |

**범위 제한 (의도적으로 뺀 것):**
- 캘린더 그리드(달력 UI)는 넣지 않는다 — 프리셋 + 네이티브 `<input type="date">` 직접 입력으로 충분하다고 판단 (2026-07-01 실사용 피드백 반영: 최초엔 프리셋만이었으나, 특정 날짜 지정이 안 되는 것이 실사용에서 문제로 확인되어 직접 입력을 추가함).
- 진행상태는 프로젝트별 커스텀 상태명이 아니라 표준 5개 그룹만 지원한다. 실제 생성 시 서버(백엔드)가 그 프로젝트의 해당 그룹 기본 상태 ID로 매핑한다.
- 라벨, 설명(description) 등 다른 필드는 이번 범위에 포함하지 않는다.

## 아이콘

Plane 실제 아이콘 에셋을 그대로 가져올 수 없으므로(라이선스/에셋 접근 불가), Plane 앱과 같은 시각 언어를 따르는 인라인 SVG를 직접 제작한다.

- **우선순위**: 막대 그래프 스타일. urgent=빨강 배지, high=막대 3개 전부 채움(빨강), medium=2개 채움(주황), low=1개 채움(회색), none=아웃라인만.
- **진행상태**: 원형 아이콘. backlog=점선 원, todo=빈 원, in progress=반원 채움(주황), done=초록 원+체크, cancelled=회색 원+X.

브레인스토밍 중 실제로 만들어 승인받은 세트를 그대로 구현에 사용한다 (`.superpowers/brainstorm/963-1782866320/content/final-mockup.html` 참고).

## 데이터 흐름 / 백엔드 변경

- **신규**: 워크스페이스 멤버 목록 조회 API (담당자 드롭다운용). `plane_api.rs`에 `list_members` 추가, 신규 Tauri 커맨드 노출.
- **신규**: 프로젝트별 상태(state) 목록 조회 및 "표준 그룹 → 실제 상태 ID" 매핑. 작업 생성 시 사용자가 고른 그룹(backlog 등)을 그 프로젝트의 해당 그룹 기본 상태 ID로 변환해서 보낸다.
- **변경**: `create_issue` 커맨드 시그니처 확장 — `project_id, name` 외에 `assignee_ids: Vec<String>, start_date: Option<String>, target_date: Option<String>, priority: String, state_group: String`을 받는다. 담당자 미선택 시 기본값(본인)을 프론트에서 채워서 보낸다.
- **변경**: `create_work_item`(plane_api.rs)의 POST 바디에 `assignees`, `start_date`, `target_date`, `priority`, `state`(매핑된 실제 ID) 필드를 추가.
- **프론트**: `shared/ipc.ts`의 `createIssue()` 시그니처 확장, `quickadd/main.ts`에 칩 툴바 렌더링 및 각 칩의 팝오버 상태 관리 추가.

## 상호작용 메모

- 칩 팝오버는 기존 프로젝트 선택 드롭다운과 동일한 패턴(클릭 → 열림, 항목 클릭 → 선택 후 닫힘, 외부 클릭/Esc로 닫힘)을 따른다.
- 팝오버가 열려 있을 때 Enter는 폼 제출이 아니라 하이라이트된 항목 선택으로 동작해야 한다 (제목 입력에서의 기존 Enter=제출과 구분).
- 트레이를 열 때마다(포커스 시) 담당자는 항상 "나"로, 날짜는 항상 "오늘"로 리셋된다(이전 입력을 기억하지 않음) — 현재 코드가 매번 title/selectedId를 리셋하는 것과 동일한 정책.
- (2026-07-01 실사용 피드백 반영) 트레이 창은 팝오버가 열려 있지 않을 때는 칩 툴바만 들어가는 낮은 높이(175px)를 유지하고, 팝오버가 열릴 때만 `setSize()`로 확장(330px)했다가 닫히면 다시 줄어든다 — 항상 큰 고정 높이를 쓰면 평소에 안 쓰는 투명 영역이 거슬린다는 피드백 때문. `.popup`은 원래 `overflow:hidden`이었으나 팝오버가 그 경계에 잘려 아예 선택이 안 되는 버그가 있어 `overflow:visible`로 바꾸고 `.popup-bottom`에 자체 하단 border-radius를 줘서 모서리를 보정했다.

## 테스트

- Rust: 표준 그룹 → 프로젝트 실제 상태 ID 매핑 함수에 대한 단위 테스트.
- 프론트: 칩 클릭 시 팝오버 열림/닫힘, 기본값 렌더링에 대한 수동 확인(현재 프로젝트에 프론트 테스트 하네스 없음 — vitest로 순수 로직만 분리해 테스트).
