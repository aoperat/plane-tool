# 상위/하위 작업 + AI 작업 분해 — 설계 스펙

- 날짜: 2026-08-18
- 상태: 설계 완료
- 선행: `2026-07-03-ai-briefing-design.md` (OpenAI 클라이언트·키링·폴백 패턴),
  `2026-08-14-issue-form-shell-design.md` (빠른 추가/수정 공통 카드 셸)

## 목적

지금 이 앱에는 작업 사이의 위아래 관계가 없다. `WorkItem`에도 `NewWorkItem`에도
`parent`가 없고, 사이드바는 모든 항목을 평평하게 나열한다.

그런데 실제로 캡처되는 일은 대개 한 덩어리가 아니다. "홍익대 취약점 문서 확인 및
조치일정 담당자에게 메일 전달"은 완료 시점이 다른 두세 개의 일이 한 줄에 눌려
들어간 것이다. 이런 항목은 상태가 "진행 중"에 오래 머물고, 어디까지 했는지는
제목만 봐서는 알 수 없다.

**두 가지를 한다.** (1) Plane의 부모-자식 관계를 앱이 읽고 쓴다. (2) 빠른 추가에서
AI가 입력을 검토해 제목을 다듬고 작업을 쪼개 제안한다.

Plane 서버는 이미 지원한다. `IssueSerializer`가 `exclude` 방식이라 `parent`가
읽기·쓰기 모두 열려 있고, 생성 시 워크스페이스·프로젝트 소속까지 검증한다
(`apps/api/plane/api/serializers/issue.py:127-136`). 제약은 서버가 아니라 이쪽에 있다.

## 핵심 설계 결정

1. **부모도 온전한 이슈다.** 담당자·마감일을 모두 채운다. 부모를 빈 껍데기로 두면
   Plane 웹에서 주인 없는 이슈로 보이고, 앱에도 "부모만 따로 끼워 넣는" 예외
   경로가 생긴다. 대신 **목록에서만 칩을 접는다** — 부모의 날짜·담당자는 자식들
   것의 요약이라 새 정보가 아니다.
2. **AI는 이름만 정한다.** 날짜·담당자·우선순위는 폼에 입력된 값을 자식이
   상속한다. AI에게 일정 감각을 기대하면 결과가 예측 불가능해지고, 어차피
   사용자가 다시 손본다.
3. **적용은 등록이 아니다.** AI 제안을 [적용]하면 폼에 반영만 되고, 확정은 언제나
   Ctrl+Enter다. "AI를 거쳐도 마지막 결정은 내가 한다"는 규칙이 흔들리지 않는다.
4. **AI는 옵트인 버튼이다.** 체크박스(다음 등록에 자동 적용)가 아니라 그때그때
   누르는 버튼이다. Ctrl+Enter는 영원히 즉시 등록으로 남는다 — 캡처 3초 원칙은
   AI가 있든 없든 훼손되지 않는다.
5. **분해 실패는 롤백하지 않는다.** 부모가 만들어진 뒤 자식 생성이 실패해도 이미
   만든 것은 지우지 않고 실패분만 재시도한다. 롤백은 성공한 작업을 지우는 더 나쁜
   실패 모드를 만든다.

## 데이터 계층

### 읽기

**절반은 이미 되어 있다.** `RawWorkItem.parent`와 `WorkItem.parent_id`는 mng
업무일지 작업 때 "이후 필요해지면 쓸 수 있도록 파싱만 해 둔다"며 들어가 있다
(`plane_api.rs:63-65`, `:428`). 남은 일은 그 값을 `WorkItemDto`에 실어 프론트로
흘려보내는 것뿐이다.

사이드바는 이미 프로젝트 전체 항목을 받아 클라이언트에서 필터링하므로
(`commands.rs:137`, `plane_api.rs:352`) **트리 조립에 추가 API 호출이 없다.**

### 하위 진행률은 서버 쪽에서 센다

사이드바 목록은 오래된 완료 항목을 걸러낸다(`filter_assigned_visible`). 그래서
프론트에서 자식을 세면 "3개 중 1개 완료"가 "1개 중 0개"로 보인다.

따라서 **필터링 전 전체 항목으로** 부모마다 `sub_total` / `sub_done`을 계산해
DTO에 실어 보낸다. 부모 행의 `1/3`과 진행 바는 이 값을 쓴다. 자식이 다른 사람
담당이거나 오래전에 완료됐어도 숫자가 맞는다.

집계 규칙의 판단 기준도 이 값이다 — `sub_total > 0`이면 부모다. 별도 플래그를
두지 않는다.

### 쓰기

`NewWorkItem`에 `parent_id: Option<&str>`를 추가하고 생성 바디에 `"parent"`를
넣는다. 값이 없으면 키 자체를 생략한다 — `description_html`과 같은 이유로 Plane
0.27+는 `null`을 400으로 거절한다(`plane_api.rs:747` 주석).

- `create_issue` 커맨드에 `parent_id` 인자 추가 (기존 호출부는 `None`).
- `create_issue_tree(project_id, parent, children)` 신설. 부모를 먼저 만들고 받은
  id로 자식을 순차 생성한다. 결과는 `{ parent_id, created: n, failed: [이름…] }`.

### 오프라인

큐 payload에 `parent_id`를 저장하고, `remap_target_id`(`offline.rs:118`)가
`target_id`뿐 아니라 payload의 `parent_id`도 치환하도록 확장한다. 부모가 아직
큐에 남아 로컬 id를 갖고 있어도, 재생 순서대로 부모 → 자식이 올바르게 연결된다.

AI 제안 버튼은 네트워크가 필요하므로 오프라인에서 비활성이다. **수동 하위 추가는
오프라인에서도 동작한다.**

## 빠른 추가 — AI 제안

### 진입

푸터의 `[추가]` 왼쪽에 `[✨ AI 제안]` 버튼을 둔다. OpenAI 키가 없으면 버튼은
보이되 누르면 설정으로 안내한다. 키·모델은 브리핑 설정을 그대로 재사용한다
(`config.rs:154`, `briefing_model`).

### 커맨드

`suggest_breakdown(title, description)` → `OpenAiClient::chat_json`. 응답:

```json
{ "title": "홍익대 취약점 대응",
  "title_changed": true,
  "children": ["취약점 문서 확인", "조치 일정 수립", "담당자에게 메일 전달"],
  "reason": "확인·조치·전달은 완료 시점이 다릅니다" }
```

프롬프트에 박는 규칙은 셋이다.

- **완료 시점이 실제로 다른 단계만 쪼갠다.** 같은 자리에서 연달아 끝나는 일은
  하위 작업이 아니다.
- **최대 4개.**
- **쪼갤 이유가 없으면 `children: []`, 제목 개선이 뚜렷하지 않으면
  `title_changed: false`.**

AI가 억지로 일을 만들지 않게 하는 것이 이 기능의 성패다. 제안이 없으면 시트는
"지금 이대로 충분합니다"만 보여주고 닫힌다.

응답 검증은 Rust에서 한다 — `children`이 4개를 넘으면 자르고, 빈 문자열·중복은
버리고, 제목이 비면 원본을 유지한다. 파싱 실패나 HTTP 오류는 폴백 없이 오류
메시지를 그대로 보여준다(브리핑과 달리 규칙 기반으로 흉내 낼 것이 없다).

### 오버레이 시트

QuickAdd 창 **안에서** 카드 위에 반투명 배경과 함께 겹쳐 뜬다. 창 크기는 바뀌지
않는다. 기존 코치마크(`.qa-coach`)의 겹침 패턴을 따른다.

- 제목 제안: 원본(취소선) → 제안. `title_changed: false`면 이 줄 자체가 없다.
- 하위 목록: 체크박스로 개별 제외, 텍스트 클릭으로 인라인 수정.
- 하위가 4개여도 시트 안쪽만 스크롤한다.
- `[취소]`(Esc) — 원래 입력 그대로. `[적용]` — 폼 반영 후 시트 닫힘.

### 적용 후

제목이 폼에 반영되고, 카드 아래에 `하위 3`이 표시된다. 담당자·날짜를 마저 만지고
평소처럼 Ctrl+Enter로 등록하면 `create_issue_tree`가 불린다. 자식은 폼의
담당자·우선순위·마감일·시작일을 그대로 상속한다 — 부모와 자식이 한 번에
만들어지는 자리라 시작일도 같은 값이 맞다(수동 하위 추가와 다른 점).

부분 실패 시: "3개 중 1개를 만들지 못했습니다"와 재시도 버튼. 이미 만들어진 것은
그대로 둔다.

## 사이드바

### 트리 조립

`src/sidebar/tree.ts`를 새로 만든다(`logic.ts`는 이미 375줄이고 성격이 다르다).
평평한 배열을 받아 `[부모, 자식…, 부모, 자식…, 독립항목…]` 순서의 렌더 목록을
돌려주는 순수 함수다.

**고아 자식은 최상위처럼 그린다.** 부모가 남의 담당이거나, 완료돼서 숨겨졌거나,
검색·필터에 걸러진 경우가 흔하다. 이때 자식을 들여쓰면 연결선이 허공에 뜬다.

### 부모 행

칩 영역을 그리지 않고 진행 바 + `1/3` + 접기 화살표를 놓는다. 접힘 상태는
프로젝트 접기와 같은 방식으로 localStorage에 둔다. 행을 클릭하면 평소처럼 수정
창이 열리고, 담당자·날짜는 거기에 그대로 있다.

자식은 한 단 들여쓰고 왼쪽에 연결선을 그린다. 자식 행 자체는 기존 행과 똑같이
동작한다(상태 변경, 팝오버, 수정 창).

### 수동 하위 추가

부모 행에 마우스를 올리면 `+`가 나타난다(프로젝트 그룹 헤더의 `.addbtn`과 같은
패턴). 누르면 한 줄 입력이 열리고 Enter로 등록 — 담당자는 나, 우선순위·마감일은
부모에서 상속하고, 시작일은 비운다(부모의 시작일은 이미 지난 날짜일 때가 많다).
상태는 프로젝트 기본 상태다.

**하위가 없는 평범한 항목에도 이 버튼을 둔다.** 그 순간 그 항목이 부모가 된다.
즉 "나중에 쪼개기"를 AI 없이도 할 수 있다.

### 자동 완료

자식을 완료로 바꿀 때 그 부모의 남은 자식이 0이 되면 부모도 완료 처리한다. 기존
낙관적 업데이트 규칙 그대로 — UI 먼저, 실패하면 둘 다 롤백.

**알려진 한계:** Plane 웹에서 자식을 닫은 경우 이 앱이 관여하지 않으므로 부모가
열린 채 남는다. 다음 동기화 때 진행률은 `3/3`으로 맞지만 부모 상태는 그대로다.

## 집계 규칙

부모와 자식이 모두 내 담당이면 4건으로 세어진다. 영역별로 다르게 처리한다.

| 영역 | 규칙 | 이유 |
|---|---|---|
| 탭 카운트 | 부모 제외 | 세는 건 실제 할 일 |
| 마감 알림 (`deadline_watch`) | 부모 제외 | 부모·자식 두 번 울리지 않게 |
| AI 브리핑 | 부모 제외 | 오늘 뭘 할지는 자식 단위 |
| mng 업무일지 | 부모만, 자식 제외 | 사람이 읽는 보고서는 묶음이 자연스러움 |

판단 기준은 `sub_total > 0`.

**"제외"는 세지 않는다는 뜻이지 숨긴다는 뜻이 아니다.** 부모 행은 사이드바
목록에 그대로 보이고, 탭 옆 숫자에서만 빠진다. 부모 1 + 자식 3이면 목록에는 4줄이
보이고 카운트는 `3`이다.

## 테스트

**Rust**

- `parent` 파싱, 생성 바디에 `parent` 포함/생략
- `sub_total`/`sub_done` 계산 (완료 자식이 필터에서 빠진 상황 포함)
- `create_issue_tree` 부분 실패 결과
- 오프라인 큐의 `parent_id` remap
- AI 응답 검증: 5개 이상 자르기, 빈 문자열·중복 제거, `children: []`,
  `title_changed: false`, 파싱 실패
- 집계 필터 (`sub_total > 0` 제외)

AI 프롬프트 조립과 응답 검증은 `src-tauri/src/breakdown.rs`로 분리해 순수 함수로
테스트한다. HTTP는 기존 `wiremock` 패턴을 쓴다(`openai.rs` 테스트 참고).

**TypeScript**

- `tree.ts`: 조립 순서, 고아 자식, 자식 없는 부모, 중첩 방지(손자는 무시)
- 진행률 표시 계산
- 오버레이 시트의 선택 상태(체크 해제·인라인 수정)를 DOM 비의존 함수로 분리해
  테스트 — `issueForm/state.ts`와 같은 방식

## 구현 순서

두 단계로 나눠 각각 릴리스할 수 있다.

1. **계층 (AI 없이)** — `parent` 읽기·쓰기, `sub_total`/`sub_done`, 사이드바 트리
   표시, 수동 하위 추가, 자동 완료, 집계 규칙. 이것만으로도 완결된 기능이다.
2. **AI 분해** — `breakdown.rs`, `suggest_breakdown` 커맨드, 오버레이 시트,
   `create_issue_tree`.

1단계 없이 2단계만 만들면 AI가 만든 하위 작업을 앱에서 볼 방법이 없다. 순서를
뒤집을 수 없다.

## 범위 밖

- **기존 이슈를 AI로 쪼개기.** 사이드바 항목을 골라 AI 분해하는 경로는 이번에
  넣지 않는다. 수동 하위 추가로 같은 일을 할 수 있고, 진입점이 늘면 검토 UI를
  QuickAdd 밖으로 꺼내야 한다.
- **손자 계층.** Plane은 더 깊은 중첩을 허용하지만 앱은 2단만 그린다. 자식의
  자식은 트리 조립에서 무시한다.
- **부모 진행률의 실시간 갱신.** Plane 웹에서 일어난 변경은 다음 동기화 때
  반영된다.
