1. 무엇이 달라지나

지금은 오늘 완료한 항목이 있는 mng 연동 프로젝트만 목록에 오릅니다 (commands.rs:1175의 if completed.is_empty() { continue; }, 그리고 그보다 앞선 1132행의 filter(|p| p.mng_link.is_some())). 그래서 사이드바에 프로젝트가 5개 있어도 이 창에는 1~2개만 뜨고, 오늘 완료가 없는 날은 "완료한 항목이 없습니다" 한 줄만 남습니다.

바꾸는 것: 사이드바에 있는 프로젝트를 전부 보여주고, 그중 고른 것만 제출합니다. 항목도 완료뿐 아니라 진행중·예정까지 보이고, 항목마다 체크가 있어 일지에 담을 것을 고릅니다.

2. 항목 단위 체크 — 무엇이 일지에 들어갈지 고르기

카드를 펼치면 완료 / 진행중 / 예정 세 그룹이 나오고, 항목마다 체크가 붙습니다. 체크를 바꾸면 아래 내용이 즉시 다시 만들어집니다 — 선택된 항목만으로 project_to_text를 다시 부르는 것뿐이라 서식은 그대로 유지됩니다.

이게 필요한 이유: 지금은 줄 하나를 빼려면 textarea에서 직접 지워야 하는데, 그 순간 main.ts:98의 if (d.content !== source) return;에 걸려 그 카드는 이후 톱니바퀴 옵션(작업 번호·우선순위·기한)이 영영 반영되지 않습니다. 체크박스는 "자동 생성" 상태를 유지한 채로 항목만 빼므로 이 거래가 사라집니다.

기본값은 완료·진행중은 체크, 예정은 해제입니다. 프로젝트 체크는 3상태로, 항목이 일부만 선택되면 중간 상태(연한 파랑 막대)가 됩니다.

5. 확정된 사항

검토 후 정해진 내용입니다. 이 목업은 아래 결정을 그대로 반영하고 있습니다.

① 기본 체크 상태 확정

오늘 완료가 있는 mng 연동 프로젝트만 체크된 채로 열립니다. 항목 기본값은 완료·진행중은 켜짐, 예정은 꺼짐. 지금 동작이 그대로 기본값이 되므로, 늘 하시던 대로면 열고 바로 제출하면 됩니다.

② 백로그·취소 확정

보여주지 않습니다. 완료·진행중·예정 세 그룹만 씁니다 — classify_groups는 지금 그대로 두면 됩니다. 백로그만 있는 프로젝트는 "담을 작업 없음"으로 잠긴 카드가 됩니다(3절 참고).

③ 항목 단위 체크 확정

넣습니다. 체크 변경 시 선택된 항목만으로 내용을 재생성합니다. 직접 편집한 카드는 기존 규칙대로 덮어쓰지 않습니다(main.ts:98).

그룹 헤더의 그룹 선택 / 그룹 해제로 한 그룹을 통째로 켜고 끌 수 있습니다. 프로젝트 체크는 전체 / 일부 / 해제 3상태입니다.

④ "내가 할당한 작업" 탭 확정

포함하지 않습니다. mng 일지는 소요 시간을 함께 적는 문서라 남에게 시킨 일은 시간 귀속이 맞지 않고, 목록도 두 배가 됩니다. 나중에 필요해지면 톱니바퀴 팝오버에 토글 한 줄로 추가할 수 있습니다.

⑤ 목록 정렬 확정

완료 있음 → 완료 없음 → 등록 완료 → 담을 작업 없음 → mng 미연동, 각 그룹 안에서는 프로젝트명 순. 오늘 손댈 것이 위로 오고, 이미 끝났거나 손댈 수 없는 것이 아래로 밀립니다.

⑥ 창 높이·스크롤 확정

기본 520 × 640 유지. 목록만 스크롤하고 헤더와 하단 제출 바는 고정합니다 — 프로젝트가 몇 개든 "몇 개 선택했는지"와 제출 버튼이 항상 보여야 합니다. 창은 이미 resizable: true라 필요하면 늘릴 수 있습니다.
