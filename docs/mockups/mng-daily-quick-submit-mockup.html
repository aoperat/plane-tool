1 · 진입점 — 사이드바 헤더

사이드바 헤더에 AI 브리핑 버튼 옆에 아이콘 버튼을 하나 추가한다. 오늘 완료한 항목이 있는 mng 연동 프로젝트 중 아직 제출 안 한 게 하나라도 있으면 주황 점이 붙는다 — 기존 "새 할당" 인박스의 점 표시(.inbox-dot)와 같은 문법이라 새 규칙을 배우지 않아도 된다. 클릭하면 2번 섹션의 창이 뜬다.

할 일 있음 — 주황 점
Plane Quick Dock 정현우

전부 제출됨 — 점 없음

2 · 제출 창 — 프로젝트별 상태

창을 열면 오늘 완료한 항목이 있고 mng 연동된 프로젝트만 카드로 나열한다(진행중·예정 이슈는 다루지 않음 — mng 일일 업무일지는 완료한 일만 대상이라 범위를 좁혔다). 각 카드는 GET 으로 실제 mng 등록 여부를 조회해 배지를 매긴다.

내용 원문은 Plane 웹의 실제 업무보고서 텍스트 포맷을 한 글자도 다르지 않게 재사용한다 — projectToText()(apps/web/.../work-report/report-text.ts:68-123)가 만드는 형식 그대로다: [프로젝트명 / 코드] 헤더, 그룹 라벨은 ✅ 완료된 일/🔄 진행 중인 일/📌 진행 예정인 일(그룹에 항목이 있을 때만), 항목 줄은 • {코드}-{번호} {이름} ({우선순위}) — {MM-DD} {배지}, 하위 항목은 └로 한 단 들여쓰기. 새로 만든 포맷이 아니라 그대로 가져온 것 — plane-tool이 완료 항목만으로 재구성한 문구를 쓰면 사람이 웹에서 복사한 것과 미묘하게 달라 헷갈린다.

완료가 아닌 그룹도 있으면 함께 들어간다 — 이 프로젝트에 오늘 기준 진행중·예정 항목이 있으면 실제 Plane과 동일하게 같은 텍스트 안에 🔄 진행 중인 일 / 📌 진행 예정인 일 섹션도 이어 붙는다(카드를 여는 트리거는 "완료 항목 있음"이지만, 일단 열리면 그 프로젝트의 전체 업무보고서 텍스트를 보여준다 — Plane 웹의 MngDailyModal에 넘기는 initialContent가 실제로 그렇게 동작한다).

소요시간 기본값은 0으로 두지 않고, 이슈에 걸린 시간 추적 데이터가 있으면(타임트래킹 기능 사용 시) 그 합계로 미리 채운다 — 없으면 0부터 스테퍼로 조절.

6 · 설계 메모

범위를 완료 항목으로만 좁힌 이유 — mng 일일 업무일지는 "오늘 한 일"을 등록하는 곳이라 진행중·예정 이슈는 대상이 아니다. 기존에 설계만 되고 구현되지 않은 "오늘 업무일지" 모달(상태 3단 전부 보여주는 것)과는 별개 기능으로 먼저 만든다 — 이쪽이 범위가 훨씬 작고, mng 프록시는 클라이언트 재구현이 애초에 불가능해 서버 API 확장이 선행돼야 하므로 작게 시작하는 편이 낫다.

서버 쪽 선행 작업 — docs/plane-work-report-mng-api.md 0절에 정리한 대로, mng/daily-reports/와 mng/projects/는 세션 인증(app/) 전용이라 plane-tool의 API 토큰으로는 못 부른다. Plane 쪽에 토큰 인증 경량 엔드포인트를 추가하는 작업이 이 목업을 실제로 만들기 전에 필요하다.

아직 안 정한 것 — 프로젝트가 많을 때 카드를 전부 펼쳐서 보여줄지 접어서 요약만 보여줄지, 소요시간 기본값을 타임트래킹 합계로 채우는 게 실제로 정확할지(수동 조정이 더 많을 수도), "확인 불가" 상태에서 "그래도 제출"을 얼마나 세게 경고할지(현재는 버튼 문구만 다르게 — 별도 확인 팝업을 넣을지는 미정).
