빠른 추가 헤더 토글 — 목업 토글을 눌러보세요. 본문이 실제로 바뀝니다.

1 · 토글 모양 세 가지

헤더는 grip + 제목 + 닫기로 비어 있는 편이라 자리는 넉넉합니다. 세 안 모두 닫기 버튼 왼쪽에 붙습니다. 헤더 전체가 창을 끄는 드래그 영역이라, 토글은 닫기 버튼처럼 드래그에서 빠지는 예외로 둡니다.

A · 아이콘 2단 세그먼트 (폭 ~56px)

현재 상태가 항상 보입니다. 켜진 쪽이 accent로 차 있어 "지금 어느 모양인지"를 누르지 않고 압니다. 필드 격자의 .seg-track을 헤더 크기로 줄인 것이라 앱 안에서 새 문법이 아닙니다 — 이미 상태·우선순위 줄에서 쓰는 모양입니다.

아이콘이 무슨 뜻인지는 호버 툴팁이 받쳐줍니다.

B · 텍스트 2단 세그먼트 (폭 ~112px)

해석할 것이 없어 가장 명확합니다. 대신 헤더 폭을 두 배 차지하고, 제목 "빠른 추가"와 시각적으로 경쟁합니다 — 헤더에서 가장 눈에 띄는 것이 창 이름이 아니라 설정 스위치가 됩니다.

C · 단일 아이콘 버튼 (폭 24px)

가장 좁지만 아이콘 하나가 두 가지를 뜻해야 합니다 — 지금 상태인지, 누르면 될 상태인지. 게다가 닫기 버튼과 크기·테두리가 같아 나란히 있으면 한 벌로 보입니다.

2 · 업데이트 후 첫 안내 (확정: 코치마크)

업데이트를 받고 빠른 추가를 처음 열 때 한 번만 뜹니다. 토글을 화살표로 직접 가리키고, 대상에도 잠깐 링을 둘러 말풍선과 토글을 눈으로 잇습니다. 알겠어요를 누르거나 토글을 직접 조작하면 사라지고 다시 뜨지 않습니다.

첫 실행 — 코치마크가 뜬 상태

제목 입력은 막지 않습니다 — 말풍선은 헤더 아래에 겹쳐 뜨지만 커서는 그대로 제목 칸에 있어, 안내를 무시하고 바로 타이핑해도 흐름이 끊기지 않습니다. 그렇게 무시한 경우에는 다음에 한 번 더 보여줍니다.

설계 메모

언제 뜨는가 — "본 적 있다" 표시를 남겨두고, 없을 때만 띄웁니다. 새로 설치한 사용자도 한 번 보게 되는데, 이 기능을 알려주는 게 목적이라 그대로 둡니다.

어디에 저장하는가 — 화면 취향이므로 백엔드 설정이 아니라 빠른 추가 창의 localStorage에 둡니다. 사이드바가 접힘 상태·탭 선택을 두는 방식과 같습니다.

토글과 설정 화면은 같은 값을 봅니다 — 헤더에서 바꾸면 설정 › 일반 › 화면의 "빠른 추가 화면" 항목도 따라 바뀌고, 반대도 마찬가지입니다. 두 개의 진실을 만들지 않습니다.

아직 안 정한 것 — 안내를 무시하고 지나갔을 때 몇 번까지 다시 보여줄지(지금 안: 2회), 그리고 헤더 토글에 단축키를 줄지 여부.
